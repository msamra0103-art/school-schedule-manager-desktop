## أول دخول للمدير الأساسي

1. افتح الموقع أو برنامج سطح المكتب مع اتصال بالإنترنت.
2. اختر **إنشاء الحساب أول مرة**.
3. استخدم البريد `m.samra0103@gmail.com` وكلمة مرور قوية لا تقل عن 8 أحرف.
4. إن طُلب تأكيد البريد، افتح رسالة Supabase ثم سجّل الدخول.
5. يربط النظام هذا البريد تلقائيًا بسجل المدير الأساسي كامل الصلاحيات.

بعد الدخول، يستطيع المدير إضافة مديرين آخرين من الإعدادات ومنحهم صلاحية كاملة أو صلاحية قسم محدد. يجب أن ينشئ كل مدير حسابه بالبريد نفسه الذي أضافه المدير الأساسي.

## رفع المشروع إلى GitHub

1. ارفع **كل محتويات الحزمة** إلى جذر المستودع، بما في ذلك `.github` و`supabase`.
2. افتح تبويب **Actions** في GitHub.
3. اختر **Build Windows Setup** ثم **Run workflow**.
4. بعد نجاح التشغيل، نزّل الملف من قسم **Artifacts** باسم `School-Schedule-Manager-Windows-Setup`.
5. الملف التنفيذي الناتج اسمه `School-Schedule-Manager-Setup-1.1.0-x64.exe`.

لإنشاء Release تلقائيًا:

```bash
git tag desktop-v1.1.0
git push origin desktop-v1.1.0
```

## نشر نسخة الويب على Vercel

1. من Vercel اختر **Add New Project** واربط مستودع GitHub.
2. لا تغيّر إعدادات البناء؛ يقرأ Vercel ملف `vercel.json` تلقائيًا.
3. اضغط **Deploy**.

أمر البناء هو `npm run web:build` ومجلد النشر هو `dist-web`.

## التشغيل أثناء التطوير

يتطلب Node.js 22 أو أحدث:

```bash
npm run desktop:start
```

## الحفظ والمزامنة

- المدير كامل الصلاحيات يمكنه تعديل الجدول كله وحفظه سحابيًا.
- حساب القسم يعمل على التبديلات الخاصة بقسمه وفق سياسات قاعدة البيانات.
- يمنع الحفظ المتزامن من جهازين الكتابة فوق نسخة أحدث دون تنبيه.
- عند انقطاع الإنترنت يعمل البرنامج على آخر نسخة محلية متاحة، ثم يعود للوضع السحابي بعد إعادة الاتصال وتسجيل الدخول.
- يظل زر النسخة الاحتياطية داخل البرنامج متاحًا للاسترجاع اليدوي.

## تشخيص نسخة سطح المكتب

ينشئ البرنامج ملف `startup.log` داخل مجلد بيانات التطبيق عند حدوث مشكلة. وقد يعرض Windows تحذير SmartScreen لأن ملف Setup غير موقّع بشهادة تجارية؛ استخدم **مزيد من المعلومات** ثم **تشغيل على أي حال** فقط عندما يكون الملف صادرًا من مستودعك الموثوق.
